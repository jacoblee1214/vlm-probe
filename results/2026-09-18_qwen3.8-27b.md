# Qwen3.8-27B 영상 인식 한계 측정

사내 공용 추론 서버에서 돌아가는 영상 인식 모델이 **무엇까지 볼 수 있고 무엇을 놓치는지**
직접 측정한 결과입니다.

| 항목 | 내용 |
| --- | --- |
| 대상 모델 | Qwen3.8-27B (vLLM 0.29.0) |
| 서버 | 사내 공용 추론 서버 (주소는 내부 문서 참조) |
| 측정일 | 2026-09-18 |
| 공통 설정 | `temperature=0`, thinking 끔 |
| 측정 도구 | `vlm_probe.py` |

정답을 따로 붙일 필요가 없도록 테스트 영상을 ffmpeg로 직접 만들어 썼습니다. 영상을 우리가
만들었으니 정답은 처음부터 알고 있는 셈이고, 덕분에 아래 수치는 스크립트만으로 그대로 다시
뽑을 수 있습니다.

## 측정 01 · 얼마나 짧은 순간까지 보이는가

10초짜리 검정 화면 영상의 5초 지점에 빨간 사각형을 아주 잠깐만 띄운 뒤, 그 사각형이
나왔는지 물었습니다. 사각형을 아예 넣지 않은 영상도 함께 넣어서, 모델이 무조건 "예"라고
찍는 것은 아닌지 확인했습니다.

| 사각형을 띄운 길이 | 시간으로 환산 | 정답 | 모델 답변 3회 | 결과 |
| --- | ---: | --- | --- | --- |
| 안 띄움 (확인용) | 0.00초 | 아니오 | 아니오 · 아니오 · 아니오 | 맞음 |
| 1장 | 0.03초 | 예 | 아니오 · 아니오 · 아니오 | **못 봄** |
| 2장 | 0.07초 | 예 | 아니오 · 아니오 · 아니오 | **못 봄** |
| 5장 | 0.17초 | 예 | 아니오 · 아니오 · 아니오 | **못 봄** |
| 15장 | 0.50초 | 예 | 예 · 예 · 예 | 맞음 |
| 30장 | 1.00초 | 예 | 예 · 예 · 예 | 맞음 |
| 90장 | 3.00초 | 예 | 예 · 예 · 예 | 맞음 |

0.17초와 0.5초 사이에서 결과가 완전히 갈립니다. 사각형을 안 띄운 영상에서 세 번 모두
"아니오"가 나온 점이 중요합니다. 모델이 판단을 포기하고 한쪽으로 찍는 것이 아니라, 정말로
그 사각형을 보지 못했다는 뜻입니다.

## 측정 02 · 영상이 길어지면 얼마나 성글게 보는가

모델은 영상을 통째로 보는 것이 아니라, 일정 간격으로 사진을 몇 장 뽑아서 봅니다. 길이만
다른 빈 영상을 넣고, 실제로 몇 장을 뽑는지 거꾸로 계산했습니다.

| 영상 길이 | 모델이 읽은 분량(토큰) | 추정 사진 장수 | 초당 읽은 장수 |
| ---: | ---: | ---: | ---: |
| 5초 | 1,562 | 9.6 | 1.91 |
| 10초 | 3,102 | 19.8 | 1.98 |
| 20초 | 6,192 | 40.4 | 2.02 |
| 60초 | 12,072 | 79.6 | **1.33** |
| 180초 | 13,052 | 86.2 | **0.48** |

20초까지는 초당 2장을 유지하지만, 전체 장수가 80장 근처에서 더 늘지 않습니다. 그래서 영상이
길어질수록 초당 읽는 장수가 반비례해서 줄어듭니다.

측정 01의 결과와 정확히 맞물립니다. 초당 2장을 뽑으면 사진 사이의 간격이 0.5초이므로,
0.5초보다 짧은 장면은 사진 사이로 빠져나갈 수 있습니다. **모델이 못 알아보는 것이 아니라,
애초에 그 장면이 담긴 사진이 없는 것입니다.**

> 장수가 멈추는 지점이 60초에서 79.6장, 180초에서 86.2장으로 완전히 일정하지는 않습니다.
> 상한을 정하는 정확한 규칙은 아직 알아내지 못했습니다.

## 측정 04 · 질문을 여러 개 한꺼번에 물어도 되는가

한 번에 여러 가지를 물으면 뒤쪽 질문을 흘리지 않을까 하는 것이 원래 가설이었습니다. 질문
8개를 1개씩, 2개씩, 4개씩, 8개씩 나눠 물으며 정답률을 비교했습니다.

| 한 번에 물은 개수 | 쉬운 질문 (무슨 색이 나왔나) | 어려운 질문 (위치·순서·개수) | 형식에 안 맞은 답변 |
| --- | ---: | ---: | ---: |
| 1개씩 | 16/16 (100%) | 16/16 (100%) | 0 |
| 2개씩 | 16/16 (100%) | 16/16 (100%) | 0 |
| 4개씩 | 16/16 (100%) | 16/16 (100%) | 0 |
| 8개씩 | 16/16 (100%) | 16/16 (100%) | 0 |

우리가 만든 영상이라 쉬웠을 가능성을 없애려고, 실제 로봇 작업 영상으로 한 번 더
확인했습니다. 이 영상에는 정답이 없지만, 정답을 몰라도 **따로 물었을 때와 묶어서 물었을 때
답이 달라지는지**는 확인할 수 있습니다.

| 조건 | 결과 |
| --- | ---: |
| 1개씩 물었을 때 같은 답이 반복되는 비율 | 16/16 |
| 8개를 묶었을 때 같은 답이 반복되는 비율 | 16/16 |
| 두 방식의 답이 서로 같은 비율 | 8/8 |

답변이 매번 달라지지는 않는지도 확인했습니다. 답변의 무작위성을 조절하는 설정을 최대로
올리든 0으로 내리든, 같은 질문 5회에 모두 같은 답이 나왔습니다.

## 측정 05 · 질문을 어떻게 쓰느냐에 따라 달라지는가

앞선 측정에서 쉬운 질문은 모두 100%가 나와 차이를 볼 수 없었습니다. 그래서 모델이 겨우
맞히는 수준의 어려운 질문 8개를 쓰고, 네 가지 조건을 비교했습니다.

### A. 관계없는 글을 앞에 길게 붙였을 때

| 붙인 글의 길이 | 모델이 읽은 분량(토큰) | 정답률 | 형식에 안 맞은 답변 |
| ---: | ---: | ---: | ---: |
| 0자 | 6,343 | 16/16 (100%) | 0 |
| 185자 | 6,432 | 16/16 (100%) | 0 |
| 917자 | 6,776 | 16/16 (100%) | 0 |
| 3,662자 | 8,066 | 16/16 (100%) | 0 |
| 10,982자 | 11,506 | 16/16 (100%) | 0 |

질문과 상관없는 글을 1만 자 넘게 붙여도 정답률이 전혀 떨어지지 않았습니다. **글이 길거나
복잡해서 성능이 나빠진다는 가설은 이 범위에서는 사실이 아닙니다.**

### B. 긴 글 안에서 질문을 어디에 두느냐

| 질문 위치 | 정답률 | 형식에 안 맞은 답변 |
| --- | ---: | ---: |
| 맨 앞 | 16/16 (100%) | 0 |
| 가운데 | 16/16 (100%) | 0 |
| 맨 뒤 | 16/16 (100%) | 0 |

2,400자쯤 되는 상관없는 글 사이에 질문을 끼워 넣어도 위치에 따른 차이가 없었습니다.

### C. 답을 미리 알려주고 물었을 때

| 미리 알려준 정보 | 정답률 | 형식에 안 맞은 답변 |
| --- | ---: | ---: |
| 없음 | 16/16 (100%) | 0 |
| 맞는 정보 | 16/16 (100%) | 0 |
| **틀린 정보** | **14/16 (87.5%)** | 0 |

**전체 측정에서 성능이 떨어진 유일한 경우입니다.** 어느 질문이 틀렸는지 확인해 보았습니다.

"이 영상에는 사각형이 두 개만 나오고, 노란 사각형이 가장 먼저 나옵니다"라는 **틀린 정보**를
미리 알려줬을 때:

| 질문 | 정답 | 아무 말 안 했을 때 | 틀린 정보를 준 뒤 |
| --- | --- | --- | --- |
| 사각형이 모두 네 개입니까? | 예 | 예 | **아니오** |
| 노란 사각형이 가장 먼저 나옵니까? | 아니오 | 아니오 | 아니오 |
| 나머지 여섯 질문 | — | 정답 | 정답 |

틀린 정보는 **개수를 묻는 질문에서만 먹혔고, 순서를 묻는 질문에서는 먹히지 않았습니다.**
모델이 무조건 사람 말에 따라가는 것이 아니라, 자기가 확신이 약한 부분에서만 끌려간다는
뜻입니다. 개수를 세는 일이 순서를 판단하는 일보다 약하다는 신호이기도 합니다.

### D. 한국어로 물을 때와 영어로 물을 때

| 언어 | 정답률 | 형식에 안 맞은 답변 |
| --- | ---: | ---: |
| 한국어 | 16/16 (100%) | 0 |
| 영어 | 16/16 (100%) | 0 |

차이가 없었습니다. 다만 짧은 예/아니오 답변만 확인한 것이며, 긴 설명을 시켰을 때 다른 언어가
섞여 나오는지는 확인하지 않았습니다.

## 결과 해석

여섯 건의 측정이 한 방향을 가리킵니다. 이 모델은 **눈에 들어온 것에 대해서는 정확하고 일관되게
판단**하지만, **무엇이 눈에 들어가는지에는 뚜렷한 한계가 있습니다.** 0.5초보다 짧은 장면과 긴
영상의 세세한 부분은 애초에 모델까지 전달되지 않습니다.

이 구분이 중요한 이유는 해결책이 정반대이기 때문입니다. **보는 것이 문제라면 모델을 여러 개로
늘려도 소용없습니다.** 모두가 똑같은 사진을 받아 보기 때문입니다. 반대로 판단이 문제라면 일을
나누는 것이 효과가 있는데, 지금 결과에는 판단이 무너지는 지점이 거의 없습니다.

### 여러 모델로 나누는 방식이 쓸모 있는 경우

지금 측정으로 근거가 확인된 용도는 일을 나눠 맡기는 것이 아니라 **영상을 잘게 잘라 더 촘촘히
보게 만드는 것**입니다. 180초 영상을 통째로 넣으면 초당 0.48장만 읽지만, 20초씩 아홉 조각으로
잘라 동시에 처리하면 조각마다 초당 2장을 유지합니다. 같은 영상을 네 배 이상 촘촘히 보게 됩니다.

반대로 "물어볼 게 많으니 나누자"거나 "글이 기니까 쪼개자"는 방식은 근거가 없습니다. 8개를 묶어
물어도, 1만 자를 붙여도 성능이 그대로였으므로 나누면 비용만 늘어납니다.

### 사용자를 위한 권장 사항

1. **영상은 20초 이내로 잘라서 넣으십시오.** 이 한 가지가 영상을 얼마나 촘촘히 보는지에 가장
   큰 영향을 미칩니다.
2. **0.5초보다 짧은 순간을 찾는 데 쓰지 마십시오.** 물건이 닿는 순간이나 미끄러지는 순간처럼
   짧게 일어나는 일은 잡히지 않습니다. 그 구간만 따로 잘라 내거나 느리게 재생한 영상을 넣어야
   합니다.
3. **물어볼 것은 한 번에 묶어서 물어도 됩니다.** 하나씩 나눠 물으면 비용과 대기 시간만
   늘어납니다.
4. **질문에 답을 미리 흘리지 마십시오.** "불량 있죠?"처럼 답을 정해 놓고 물으면 모델이
   끌려갑니다. 특히 개수를 묻는 질문에서 위험합니다.
5. **thinking 기능은 필요할 때만 켜십시오.** 기본값이 켜져 있어서, 끄지 않으면 영어로 된 생각
   과정이 먼저 길게 나오면서 정작 답변이 잘립니다.

## 아직 확인하지 못한 것

이 문서는 기준을 잡는 첫 단계이지 완결된 평가가 아닙니다.

- **없는 것을 있다고 말하는 비율.** 영상에 없는 물건을 있는 것처럼 전제하고 물었을 때 아니라고
  하는지 그럴듯하게 설명하는지는 재지 않았습니다. 여러 사람이 쓰는 환경에서 가장 먼저 문제를
  일으킬 가능성이 높습니다.
- **영상을 거꾸로 돌리거나 순서를 뒤섞었을 때.** 답이 그대로라면 모델이 영상을 보지 않고
  그럴듯한 말만 만들어 내고 있다는 뜻입니다.
- **실제 촬영 영상에서의 최소 크기.** 8픽셀은 가장 유리한 조건의 값입니다.
- **개수 세기와 위치 짚기.** 측정 05에서 개수 세기가 상대적으로 약하다는 단서가 나왔으므로,
  이 부분을 따로 파고들 가치가 있습니다.
- **긴 설명을 시켰을 때.** 모든 측정이 예/아니오로 답하는 질문이었습니다. 자유롭게 설명하게
  하면 결과가 다를 수 있습니다.
- **한국어 답변의 안정성.** 긴 답변에서 다른 언어가 섞여 나오는지 확인하지 않았습니다.

## 다시 측정하는 방법

테스트 영상은 ffmpeg로 그때그때 만들어져 서버로 자동 전송됩니다. 따로 준비할 영상 자료도,
정답을 적어 둔 파일도 필요하지 않습니다.

```bash
# 측정 01 · 얼마나 짧은 순간까지 보이는가
python3 vlm_probe.py temporal

# 측정 02 · 영상 길이별로 초당 몇 장을 읽는가
python3 vlm_probe.py sampling
```
